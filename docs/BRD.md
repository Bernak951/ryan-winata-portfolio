# 1. Project Overview

## 1.1 Project Name

Portfolio V3 — Ryan Winata Personal Portfolio Website

## 1.2 Project Type

Professional personal portfolio website.

## 1.3 Project Purpose

Portfolio V3 is a custom-built personal portfolio website designed to
present Ryan Winata's professional profile, experience, projects,
certifications, research, and technical capabilities.

The website is intended to support professional branding and recruiter
evaluation while also demonstrating the ability to design, structure,
develop, test, and maintain a digital solution.

# 28. Development Workflow

The standard workflow is:

1. Define requirement.
2. Review BRD.
3. Review Roadmap.
4. Review Architecture.
5. Review Coding Convention.
6. Inspect relevant existing code.
7. Create implementation plan.
8. Review the plan.
9. Ask Kiro to implement.
10. Inspect code changes.
11. Run the website locally.
12. Test functionality.
13. Test responsive behavior.
14. Review visual result.
15. Fix issues.
16. Review Git diff.
17. Commit the completed feature.
18. Update CHANGELOG when appropriate.
19. Push to GitHub.

---

# 29. Git Commit Principles

Commits should represent meaningful changes.

Preferred format:

type(scope): description

Examples:

feat(projects): implement project card layout

feat(experience): add experience timeline

feat(responsive): optimize mobile layout

fix(about): correct section spacing

fix(navbar): improve mobile navigation

refactor(hero): simplify hero structure

docs(brd): update portfolio requirements

Commits should remain concise and descriptive.

Kiro should not automatically create commits unless explicitly requested.
